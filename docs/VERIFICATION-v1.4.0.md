# Aurio v1.4.0 の検証

基準は公開版 v1.3.0（`1391418`、versionCode 32）。対象はこの報告と同じコミットの v1.4.0（versionCode 33）です。アプリIDは `jp.noppy.lumamusic` です。

試験には Android エミュレーター（API 37、x86_64、540 × 1200、密度214 dpi）を使いました。音源は合成PCMと、そのPCMから作ったFLAC・MP3・AACです。PCM比較点はAurioの音声処理後、Androidの出力前です。

## 実装と原因

| 対象 | v1.3.0で確認したこと | v1.4.0の変更 |
|---|---|---|
| 曲頭の音 | WAVの自動遷移で冒頭欠落を再現できませんでした。USBの形式一致を優先する経路では、曲変更とDSP状態の変化を受けて使用中のミキサー設定を解除していました。 | 形式一致の設定はPCM出力の構成が変わるまで維持します。出力先や出力形式が変わった場合の判定と、ビットパーフェクト試行時の無加工判定は引き続き行います。物理出力で報告された欠落の原因は未確定です。 |
| LAME/Xing MP3 | Media3 1.11.1で48 kHzの冒頭PCMが参照より529フレーム（約11 ms）進んでいました。先頭1,800フレームを照合すると、参照を529フレームずらしたときの平均絶対誤差は16-bit PCMの0.08でした。 | MediaCodecとMedia3による遅延補正の重複を解消した公式のMedia3 1.12.0-rc01を使います。 |
| 一時停止中の曲送り | 曲送りは次の曲や前の曲に移動し、再生は一時停止したままでした。 | MediaSession側で移動の可否を確認し、移動先を曲頭から再生します。出力切断やフォーカス喪失後の再開抑止を確認し、スワイプ中に曲が変わった場合は古い移動先を使いません。 |
| 全曲シャッフル | ライブラリの楽曲一覧には開始ボタンがありませんでした。 | 「全曲シャッフル」で表示中の楽曲一覧から開始曲を選びます。既存のSmart Shuffleが残りの曲順を管理します。曲データは一覧から受け取り、連続タップによる同じキューの再設定を抑えます。 |

デコード、遅延・パディング補正はMedia3が行います。元のキュー順を維持し、Media3タイムラインとSmart Shuffleで再生順を管理します。 [Media3のプレイリスト仕様](https://developer.android.com/media/media3/exoplayer/playlists) · [AudioSinkのバッファ仕様](https://developer.android.com/reference/androidx/media3/exoplayer/audio/AudioSink)

Media3のリリース候補を採用したのは、検証日時点でMP3の修正を含む安定版が未公開だったためです。AurioのminSdkは29です。APKは68,529,134バイトから68,602,414バイトになりました。 [Media3のリリースノート](https://developer.android.com/jetpack/androidx/releases/media3#1.12.0-rc01) · [MP3の修正記録](https://github.com/androidx/media/issues/3425)

## 主な変更ファイル

- `PlaybackService.kt`、`PlaybackController.kt`、`QueueOrder.kt` に曲送りとシャッフル開始の処理を追加しました。
- `OutputMonitor.kt` で、曲変更時に形式一致のミキサー設定を維持するようにしました。
- `LibraryScreen.kt` と `LumaViewModel.kt` を全曲シャッフルに接続しました。
- 計装テストにPCM比較、キュー操作、上書き、ライブラリのボタン操作を追加しました。

## リリース判定

署名済みの評価用APKは `release/Aurio-1.4.0.apk` です。アプリIDと署名証明書は公開版v1.3.0と一致します。SHA-256は同じフォルダーの `Aurio-1.4.0-SHA256SUMS.txt` に記録しました。

正式公開は保留です。USB-C・Bluetooth・内蔵スピーカーの物理出力と、切断・フォーカス喪失時の挙動を実機で確認する必要があります。起動時間の差も引き続き確認が必要です。

## 試験用音源の作り方

WAVの比較音源は `PlaybackHeadDeviceTest.kt` が生成します。圧縮形式用の音源は48 kHzのモノラルで、最初の50 msに1 kHzのトーンを入れています。以下のコマンドで元のWAVと比較用PCMを生成できます。

```sh
ffmpeg -f lavfi -i "sine=frequency=1000:sample_rate=48000:duration=0.05" -af "apad,atrim=duration=0.3" -c:a pcm_s16le head.wav
ffmpeg -i head.wav -c:a flac head.flac
ffmpeg -i head.wav -c:a libmp3lame head.mp3
ffmpeg -i head.wav -c:a aac head.m4a
ffmpeg -i head.flac -f s16le head-flac.pcm
ffmpeg -i head.mp3 -f s16le head-mp3.pcm
ffmpeg -i head.m4a -f s16le head-m4a.pcm
```
